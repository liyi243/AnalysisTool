## 1. 项目背景与目标

在智能电表用电信息采集系统中，集中器与本地通信模块（载波模块、微功率无线模块）之间遵循 **Q/GDW 376.2《电力用户用电信息采集系统通信协议 第2部分：集中器本地通信模块接口协议》** 通信。协议调试、现场联调、抓包日志分析过程中，工程师经常需要人工逐字节比对报文，效率低且易出错。

本项目目标是开发一款**离线桌面版协议解析工具**，从 376.2 协议解析做起，实现：

- 报文（帧）的**准确解析**：逐字段拆解、含义翻译、校验验证；
- **美观易用**的图形界面，让"看懂一帧报文"变成一眼可见的事；
- 支持**单帧、多帧字节流、文本文件**三种来源的帧提取与解析；
- 为后续扩展 DLT645、376.1、698.45 等协议预留插件化架构。

## 2. 用户与使用场景

| 用户 | 场景 |
|---|---|
| 协议软件工程师 | 开发/调试集中器与模块通信程序，核对报文字段 |
| 现场调试人员 | 串口/网络抓包得到 hex 日志，快速定位通信问题 |
| 测试人员 | 用样例报文做协议一致性检查 |
| 售前/技术支持 | 向客户演示、解释报文内容 |

典型输入：串口助手复制的 hex 文本、日志文件（含时间戳/中文注释的混合文本）、`.bin` 裸字节流文件。

## 3. 功能需求

### 3.1 需求总表

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-1 | 单帧解析 | 输入一帧 hex 报文，输出链路层/应用层逐字段解析 | P0 |
| FR-2 | 多帧解析 | 连续字节流自动分帧（含粘包、断帧、噪声字节），逐帧列表展示 | P0 |
| FR-3 | 文件提取解析 | 从 `.txt/.log/.csv/.hex` 文本及 `.bin` 二进制文件中提取帧并解析 | P0 |
| FR-4 | 链路层解析 | 起始符/长度L/控制码C（含位解释与功能码）/地址域/AFN/SEQ/用户数据/CS/结束符 | P0 |
| FR-5 | 应用层解析 | AFN 分类解析数据单元；中继类报文内嵌 DLT645 报文的识别与解析 | P0 |
| FR-6 | 校验与错误诊断 | 长度一致性校验、CS 累加和校验；错误帧给出原因与偏移位置 | P0 |
| FR-7 | 字节映射可视化 | 字节网格按字段着色 + 图例 + 悬停提示，点击定位字段树 | P0 |
| FR-8 | 解析结果导出 | 导出 JSON / TXT 解析报告；一键复制解析结果 | P1 |
| FR-9 | 示例帧库 | 内置典型样例帧（链路检测、中继抄读、中继数据等）一键填充 | P1 |
| FR-10 | 输入规范化 | 自动去除注释/时间戳/非法字符，兼容空格、逗号、`68H`、`0x68` 等写法 | P1 |
| FR-11 | 统计与状态 | 帧数、上/下行统计、校验失败数，状态栏实时反馈 | P1 |

### 3.2 解析准确性要求（P0 核心验收项）

- 帧定位必须严格：`68` 开头、按协议长度 L 定界、`16` 结尾、CS 校验通过的才判定为有效帧；
- 对校验失败或长度异常的字节段，单独归入"异常/待定"分类并给出**具体原因**（如"CS 校验失败：计算 XX ≠ 帧内 YY"），不与有效帧混淆；
- 多帧扫描在含噪声、含部分损坏帧的流中必须能**重同步**继续扫描后续帧；
- 字段解码必须依据协议字典（控制码功能码表、AFN 表、错误码表），无法识别的编码明确显示"保留/未定义"，不得臆造含义。

### 3.3 文本文件提取规则（FR-3 细化）

1. 支持逐行扫描：剔除常见时间戳（`[2026-11-16 12:00:00.123]`、`2026/11/16 12:00:00`）、中文注释（`//`、`#`、`--` 之后的内容）、行号前缀；
2. 从剩余文本中以连续 2 位 hex 字符为单位收集候选字节流，支持 `68 32`、`68,32`、`68-32`、`68H 32H`、`0x68 0x32`、`6832` 等写法；
3. 对候选字节流执行协议分帧扫描（68…16、长度定界、CS 校验），因此时间戳中恰好形如 hex 的数字（如 `12:00:00`）不会误入帧内——CS 校验会将其排除在帧边界之外；
4. 二进制文件按裸字节流扫描。

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | **界面美观**（用户指定最高优先级） | 现代深色主题、统一设计语言、字节映射彩色高亮、布局对齐、手感细腻（悬停/选中反馈） |
| NFR-2 | **解析准确**（用户指定最高优先级） | 见 3.2，且内置样例帧 100% 解析通过（含单元测试） |
| NFR-3 | 易操作性 | 粘贴即解析（Ctrl+Enter）、示例一键填充、拖拽文件、结果一键复制；单窗口完成全部操作 |
| NFR-4 | 性能 | ≤10MB 文件解析 ≤3 秒；单帧解析即时（<50ms） |
| NFR-5 | 可扩展 | 协议引擎与 GUI 解耦；预留协议插件接口，后续可接入 DLT645/376.1/698 |
| NFR-6 | 可分发 | PyInstaller 打包为 Windows 可执行文件，免安装运行 |
| NFR-7 | 离线可用 | 运行期不依赖网络 |

## 5. 输入规格

| 输入 | 形式 | 示例 |
|---|---|---|
| 单帧 hex | 任意分隔符 hex 串 | `68 25 00 68 0B ... 16` |
| 多帧/混流 hex | 多帧连续或换行分隔、可夹带噪声 | `68...16 68...16` |
| 文本文件 | 抓包日志、串口记录、带注释报文 | `2026-11-16 10:00:00 上行: 68 ... 16` |
| 二进制文件 | `.bin/.dat` 裸流 | 原始字节 |

## 6. 输出规格

1. **帧列表**：序号、方向（上行/下行）、长度、控制码、功能、AFN、摘要、校验状态；
2. **单帧详情**：字节映射图（着色）、字段树（字段名/偏移/原始值/解析值）、解析要点摘要、错误告警；
3. **导出报告**：JSON（结构化，供程序处理）、TXT（人读报告）。

## 7. 约束与边界

- 首期仅实现 376.2（链路层 + 常用应用层 AFN 数据单元）；内嵌 645 报文做结构级解析（帧结构、控制码、数据标识字典对常用项）；
- 以主流资料公开记载的 376.2 帧格式为准（调研笔记见 `resources/research/`），对存在争议的细节在 UI 中"保留原值"并注明；
- 不含串口实时抓包（后续版本可扩展）。

## 8. 验收标准

1. 3 个优先级 P0 全部实现；样例帧库所有帧解析结果与人工核对一致；
2. 单元测试覆盖：帧定位、L 校验、CS 校验、控制码/AFN 解码、多帧重同步、文本提取（含时间戳干扰用例）；
3. 界面按《04-UI 设计说明书》实现并通过截图验收；
4. 可执行文件在干净 Windows 环境（无 Python）下可启动并完成一次完整解析流程。
