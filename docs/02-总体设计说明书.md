## 2. 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                      表现层 (src/gui)                        │
│  MainWindow  InputPanel  FrameListTable  HexByteMapViewer    │
│  FieldTreePanel  SummaryCard  ExportDialog  Theme(QSS)       │
├─────────────────────────────────────────────────────────────┤
│                     服务层 (src/app_svc)                     │
│  ParsePipeline（调度引擎）  ReportExporter（JSON/TXT导出）    │

├─────────────────────────────────────────────────────────────┤
│                协议引擎层 (src/qgdw3762)  ← 纯Python、无GUI依赖 │
│  scanner.py   frame.py    applayer.py   consts.py   six45.py │
```

**分层原则**：

1. 协议引擎层不 import 任何 GUI 模块，可独立用于 CLI 与单元测试；
2. 表现层只调用服务层与引擎层的公共 API；
3. 未来接入新协议（645/376.1/698）时，在引擎层新增平行包并注册到服务层协议注册表，GUI 通过"协议选择"切换（预留）。

## 4. 核心数据模型

```python
@dataclass
class Field:
    name: str            # 字段名，如 "控制码C"
    offset: int          # 相对帧起始字节偏移
    length: int          # 字节数
    raw: str             # 原始hex，如 "0B"
    value: str           # 解析值，如 "下行帧 / 读数据(功能码11)"；无解析时=raw
    note: str = ""       # 备注（如 bit 位解释）
    kind: str = "data"   # color 语义分组: start/len/ctrl/addr/afn/seq/data/cs/end/err
    children: list["Field"] = field(default_factory=list)
    error: bool = False  # 该字段是否校验失败

@dataclass
class ParsedFrame:
    raw: bytes
    start: int           # 在源数据中的偏移（多帧场景）
    fields: list[Field]  # 链路层字段树（应用层作为 children 挂在"用户数据"下）
    direction: str       # "下行(集中器→模块)" / "上行(模块→集中器)" / "未知"
    summary: str         # 一句话摘要（用于帧列表）
    errors: list[str]    # 诊断信息
    cs_ok: bool
    valid: bool          # 结构完整且CS通过
```

## 5. 数据流

```
输入(hex文本/文件) → TextNormalizer 规范化 → bytes
    → scanner.scan_frames() 逐字节滑窗定位帧候选
        ├─ 68✓ L=总长✓ 16✓ CS✓ → 有效帧 → frame.parse_frame()
        └─ 校验失败 → 异常帧（记录原因与偏移，窗口推进1字节重同步）
    → 逐帧 applayer 解析（AFN 分派 / 内嵌645）
    → ParseResult{frames, stats, warnings} → GUI 渲染 / 导出
```

**滑窗分帧算法**（`scan_frames`，依据 376.2 帧格式：单起始符、L=整帧总长）：

```
i = 0
while i < n:
    if data[i] != 0x68: i += 1; continue
    L = data[i+1] | data[i+2]<<8        # 2字节小端，L=整帧总长
    if L 越界: i += 1; continue
    if 长度域重复且低2位=10B 且 376.1 形态自洽:
        告警"疑似 376.1 帧"; i += 1; continue
    end = i + L                          # L=总长 → 帧体 [i, i+L)
    if end > n: 告警"帧体不完整"; i += 1; continue
    if data[end-1] != 0x16: i += 1; continue
    CS = sum(data[i+3 : end-2]) & 0xFF   # C 起至数据末
    if CS 匹配: 输出有效帧; i = end       # 粘包自动续扫
    else: 输出异常帧（记录原因）; i += 1  # 重同步
```

## 7. 服务层 API（GUI 调用）

```python
class ParsePipeline:
    def parse_text(self, text: str) -> ParseResult          # 单帧/多帧统一入口
    def parse_file(self, path: Path) -> ParseResult         # 自动判别文本/二进制

@dataclass
class ParseResult:
    frames: list[ParsedFrame]
    stats: dict          # total/up/down/invalid/bytes...
    warnings: list[str]
```

## 8. 错误处理与诊断策略

| 异常情形 | 处理 |
|---|---|
| 无 68 起始 | 提示"未检测到帧起始符 68H" |
| L 与实际距离不符 | 归入异常帧，报告"长度域(=N)与帧定界不符" |
| CS 不符 | 归入异常帧，报告"计算和 XX ≠ 帧内 YY"（仍展示字段，但标记红色） |
| AFN/Fn 未知 | 显示 "备用/未定义(0xXX)"，不臆造 |
| 空输入 | 输入面板行内提示 |
| 大文件 | 扫描在后台线程执行，UI 显示进度（预留 QThread） |
