## 0. 结论速览（TL;DR）

| 问题 | 结论 |
|---|---|
| 起始符 | **单个** 68H（帧头）。**没有第二起始符 68H**（这点与 376.1 完全不同） |
| 长度域 L | **2 字节，BIN 码，低字节在前**。**L = 整帧总字节数**（含 68H、L 域自身 2 字节、C、用户数据、CS、16H）。等价表述（标准原文）：L = 用户数据长度 L1 + 6，固定 6 字节 = 起始符(1)+长度域(2)+控制域(1)+校验和(1)+结束符(1)。**L ≤ 65535，D15/D14 等位无任何标志含义**（纯 BIN） |
| 控制码 C | 1 字节：**D7=DIR 传输方向**（0=集中器下行，1=模块上行），**D6=PRM 启动标志**（1=启动站，0=从动站），**D5~D0=通信方式**（6 bit 数值：1=集中式路由载波、2=分布式路由载波、3=HPLC 载波[2019 版]/宽带载波[2013 版]、10=微功率无线、20=以太网）。**C 域没有"功能码"字段**——链路检测等功能由应用层 AFN 表达 |
| 地址域 A | **BCD 码，每个地址 6 字节**（12 位 MAC 地址）。出现条件：信息域中"通信模块标识"=1（对从节点操作）时才有地址域；=0 时无地址域。A1=源地址、A2=中继地址（仅下行、个数=中继级别）、A3=目的地址。地址是**主节点/从节点（载波/微功率节点）的 MAC 地址**，不是集中器终端地址。广播时 A3=999999999999H |
| 帧序域 SEQ | **376.2 没有帧序域 SEQ**（这是 376.1 的概念）。等价机制：信息域 R 的第 6 字节"报文序列号"（0~255 循环，匹配上下行请求/应答）+ AFN=00H 确认/否认帧 |
| 用户数据 | 信息域 R(6B) + 地址域 A(变长) + **AFN(1B) + 数据单元标识 DT(2B) + 数据单元**。**没有 376.1 的 DA（信息点）**。Fn = DT2×8 + (DT1 中置位位序号)，n=1~248 |
| 校验和 CS | 1 字节，**CS = 控制域 C + 用户数据区（R/A/AFN/DT/数据）全部字节的算术和，mod 256**（"不考虑溢出位"）。即帧内偏移 3 起到 CS 前一字节止。**不含 68H、长度域、CS 自身、16H** |
| 结束符 | 16H |
| 最小帧 | 15 字节（68H+L+C+R+AFN+DT+CS+16H，即 L=0FH 的无地址帧） |
| 传输规则 | 字节内**低位（LSB）先传**；多字节**低字节在前**；异步 8 数据位+偶校验+1 停止位（8E1），默认 9600 bit/s；3.3V TTL 串口 |

- 376.1（Q/GDW 10376.1）：主站 ↔ 采集终端（集中器）的远程通信协议；
- DL/T 645：电能表 ↔ 通信模块的应用层规约，常以"透明转发"方式内嵌于 376.2 的数据转发/并发抄表数据单元中（AFN=02H、AFN=F1H，见 §2.6）。

## 2. 完整帧结构逐字节说明

### 2.1 帧总图

标准原文 5.3.1：**"本部分采用 GB/T 18657.1—2002 的 6.2.4 FT1.2 异步式传输帧格式"**，帧格式图为：

```
起始字符（68H）   ← 固定报文头（仅一个起始符！）
长度 L            ← 2 字节，BIN，低字节在前
控制域 C          ← 1 字节
用户数据          ← 用户数据区（= 信息域R + 地址域A + 应用数据域）
校验和 CS         ← 帧校验和
结束字符（16H）
```

对应标准原文 5.3.3：**"长度 L 是指帧数据的总长度，由 2 字节组成，BIN 格式，包括用户数据长度 L1 和 6 个字节的固定长度（起始字符、长度、控制域、校验和、结束字符），长度 L 不大于 65535。"**

以及 5.3.2 接收校验规则 d)2)：**"每帧接收的字符数为用户数据长度 L1+6"**（再次印证 L=L1+6=整帧总长）。

用户数据区格式（标准 6.1，图 4）：

```
信息域 R          ← 6 字节（下行/上行内容不同，见 §2.4）
地址域 A          ← 0 / 6 / 12 / 18 / … 字节（视通信模块标识与中继级别）
应用功能码 AFN    ← 1 字节，二进制编码
数据单元标识 DT   ← 2 字节（DT1 + DT2）
数据单元          ← 变长

注（标准原文）：用户数据区中所有预留部分均用 0 填充。
```

**逐字节偏移表**（无地址域帧，即通信模块标识=0 的最常见帧）：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | 起始符 | 固定 68H |
| 1~2 | 2 | 长度 L | BIN，**小端**（低字节在偏移 1）。值=整帧总字节数 |
| 3 | 1 | 控制域 C | D7=DIR，D6=PRM，D5~D0=通信方式 |
| 4~9 | 6 | 信息域 R | 上下行位定义不同（§2.4） |
| 10~ | 变长 | 地址域 A | 仅当 R1.D2（通信模块标识）=1；A1(6B)+A2(6B×中继级别，仅下行)+A3(6B)（§2.5） |
| … | 1 | AFN | 应用功能码（§2.6） |
| … | 2 | DT | DT1+DT2，构成 Fn（§2.6） |
| … | n | 数据单元 | 按 AFN/Fn 定义 |
| 倒数第2 | 1 | CS | sum(偏移3..最后数据字节) mod 256 |
| 末 | 1 | 结束符 | 固定 16H |

四套实现中的偏移锚点（代码级证据）：

- QGDW1376_2 `GDW1376_2.c print_struct()`：`L = pin[1]|pin[2]<<8`；`C = pin[3]`；信息域 R=`pin[4..9]`；`pin[4]&0x04`（通信模块标识）为 1 时 A1=`pin[10..15]`、中继 A2 自 `pin[16]` 起每 6 字节一个（个数=`pin[4]>>4`，仅下行）、A3 在其后；`user_data_pos`（AFN 位置）= 无地址 10 / 有地址 `22+中继数×6`；CS=`pin[len-2]`。
- QGDW1376_2 `chkfrm.c`：`packlen = pin[1]|pin[2]<<8;` 并要求 `packlen == len`（**L==帧总长**，大于则"粘包"，小于则长度无效）；`get_cs(pin+3, len-5)`（**CS 从偏移 3（C）起累加 len-5 字节，即到偏移 len-3（数据末）**）。
- Xsoda `parse.cpp`：`dg->len = *(__u16*)(packet+1)`（小端 2 字节）；`packet[dg->len-1]==0x16`；CS 循环 `for(i=3; i<dg->len-2; i++) sum+=packet[i]` 后与 `packet[dg->len-2]` 比较；地址域解析逻辑与上完全相同（上行无 A2）。
- rf_ctrl_monitor `LinkProtocol.cpp`：`length = at(1)|at(2)<<8`，`length != raw.size()` 报"帧长度异常"；checksum 同上。

### 2.2 起始符：只有一个 68H

- 标准图 2 中 68H 仅出现一次（"固定报文头"只含 起始字符+长度）。
- 四套实现均只校验 `pin[0]==0x68`，没有任何一处检查第二起始符。
- **辨误**：网上不少资料（包括 GitHub [dufeiran/Rosetta-Parse](https://github.com/dufeiran/Rosetta-Parse) 的 `schemas/gw3762/base.yaml`，其帧注释为 `68H | L1L2 | L1L2 | 68H | C | A(5) | AFN | SEQ | DATA | CS | 16H`）把 **376.1 的帧结构套在 376.2 名下**（双 68H、长度重复两次、5 字节地址、C 域带 FCB/FCV 功能码、长度低 14 位掩码 0x3FFF）。该 YAML 自己的 description 也写的是"主站与采集终端"。**与官方标准原文和四套实现冲突，判定为错误，解析工具不要采用**（详见 §9 冲突清单）。

### 2.3 长度域 L：整帧总长，无标志位

- **字节数**：2 字节，BIN 编码，**低字节在前**（标准 5.2："链路层传输顺序为低位在前，高位在后；低字节在前，高字节在后"）。
- **含义**：`L = 整帧总字节数 = 用户数据长度 L1 + 6`。
  - L1（用户数据）= 信息域 R + 地址域 A + AFN + DT + 数据单元（**不含控制域 C**）；
  - 固定 6 字节 = 起始符 68H(1) + 长度域自身(2) + 控制域 C(1) + 校验和 CS(1) + 结束符 16H(1)。
  - 注意两个容易搞混的表述：`L == 帧总字节数`（实现校验式）与 `L == L1 + 6`（标准文字表述）是同一个东西，L1 不含 C 但 6 里含 C。
- **包含/不包含**：L **包含** 68H、长度域自身、控制域 C、地址域、用户数据、CS、16H；单独看"不含什么"没有意义——它是总长。这与 376.1 的 L（只覆盖 C~数据末、且低 2 位是规约标志）完全不同，见 §7。
- **D15/D14 等 bit 有无标志含义**：**没有**。标准只说"BIN 格式…不大于 65535"，没有任何保留位/方向位定义（有此疑问通常是因为 376.1 的 L 低 2 位 D0=0、D1=1 是规约标志，或 DL/T 698.45 的长度定义，均不适用于 376.2）。
- **工程含义**：收到字节流时，`L` 可以直接用来切帧/判粘包（`L < 已收字节数` → 粘包；`L > 已收字节数` → 帧未收完；QGDW1376_2 分别返回 ERR_CHKFRM_LEN_LONG / ERR_CHKFRM_LEN）。

### 2.4 控制域 C：D7=DIR、D6=PRM、D5~D0=通信方式

标准原文 5.3.4.1（图 3）：

> "控制域 C 表示报文的传输方向、启动标志和通信模块的通信方式类型信息，由 1 字节组成"
> "**DIR=0：表示此帧报文是由集中器发出的下行报文；DIR=1：表示此帧报文是由通信模块发出的上行报文。**"

标准原文 5.3.4.2（表 1）：

| PRM | 说明 |
|---|---|
| 0 | 表示此帧报文来自从动站 |
| 1 | 表示此帧报文来自启动站 |

标准原文 5.3.4.3（表 2，通信方式，D5~D0 共 6 位，0~63）：

| 值 | 通信方式（10376.2—2019） | 说明 |
|---|---|---|
| 0 | 保留 | — |
| 1 | 集中式路由载波通信 | 指采用集中式路由方案的电力线窄带载波通信 |
| 2 | 分布式路由载波通信 | 指采用分布式路由方案的电力线窄带载波通信 |
| 3 | HPLC 载波通信 | 指采用电力线 HPLC 载波通信（**2013 版此值为"宽带载波通信"**） |
| 4~9 | 备用 | 2024 版据 South 工具 4=双模通信(HDC)（待确认） |
| 10 | 微功率无线通信 | 指采用微功率无线组网的通信 |
| 11~19 | 备用 | — |
| 20 | 以太网通信 | 指基于 TCP/IP 协议的以太网方式的通信 |
| 21~63 | 备用 | — |

**重要辨误**：任务书里"控制码功能码表（01 链路检测、读数据、写数据…）"是 **376.1 控制域 D3~D0 功能码**的概念（376.1：0=确认否认、1=复位、8=链路检测等）。**376.2 的 C 域没有功能码**——"链路检测/读数据/写数据"等全部由应用层 **AFN（00H~15H、F0H、F1H）+ Fn** 表达（见 §2.6）。376.2 中也没有"写数据/读中继数据"这类 C 域功能码：读=AFN=03H/10H/14H，设置=AFN=04H/05H/11H。

**常见 C 值速查**（实测帧统计）：

| C 值 | 二进制 | 含义 |
|---|---|---|
| 41H | 0,1,000001 | 下行、启动站、集中式路由载波（最常见下行） |
| C1H | 1,1,000001 | 上行、启动站（模块应答/主动上报，最常见上行） |
| 43H | 0,1,000011 | 下行、启动站、HPLC 载波（2019 版） |
| C3H | 1,1,000011 | 上行、启动站、HPLC 载波 |
| 83H | 1,0,000011 | 上行、**从动站**、HPLC 载波（模块被动响应场景） |
| 40H/42H/44H… | 0,1,xxxxxx | 其他通信方式下行（微功率 4AH=0,1,001010 等） |

（PRM 与 DIR 组合：下行主动=40H|通信方式，下行从动=00H|通信方式；上行主动=C0H|通信方式，上行从动=80H|通信方式。）

### 2.5 信息域 R（6 字节，上下行不同）

这是 376.2 独有的域（376.1 没有），位于 C 之后。标准 6.2，下行=表 4、上行=表 5，均为 BS（独立位组合）+BIN 混合，共 6 字节。

**下行报文信息域（表 4）**：

| 字节 | 位定义 |
|---|---|
| R1 | D7~D4=**中继级别**（0~15，0=无中继）；D3=**冲突检测**（0=不进行，1=要进行）；D2=**通信模块标识**（0=对主节点操作，1=对从节点操作）；D1=**附属节点标识**（0=无附加节点，1=有）；D0=**路由标识**（0=带路由/路由模式，1=不带路由/旁路模式） |
| R2 | D7~D4=**纠错编码标识**（0=信道未编码，1=RS 编码，2~15 保留）；D3~D0=**信道标识**（0=不分信道，1~15=第 1~15 信道） |
| R3 | **预计应答字节数**（BIN，0~255，用于计算延时等待；0=默认延时） |
| R4~R5 | D15=**速率单位标识**（0=bit/s，1=kbit/s）+ D14~D0=**通信速率**（BIN，0=默认通信速率）——2 字节小端组合 |
| R6 | **报文序列号**（BIN 0~255，匹配上下行请求/应答对应关系，循环使用） |

**上行报文信息域（表 5）**：

| 字节 | 位定义 |
|---|---|
| R1 | D7~D4=**中继级别**（0~15）；D3=0；D2=**通信模块标识**；D1=0；D0=**路由标识** |
| R2 | D7~D4=0；D3~D0=**信道标识** |
| R3 | D7~D4=**电能表通道特征**（0=保留；1=单相单信道；2=单相两信道；3=单相三信道；4=三相三信道；5~15 保留）；D3~D0=**实测相线标识**（0=不确定，1~3=第 1~3 相） |
| R4 | D7~D4=**末级应答信号品质**；D3~D0=**末级命令信号品质**（15 级，0=无信号品质，1=最低） |
| R5 | D7~D1=预留；D0=**事件标志**（0=无上报事件，1=有上报事件） |
| R6 | **报文序列号**（BIN 0~255） |

实现佐证：QGDW1376_2 `GDW1376_2.c print_struct()` 按此逐位解析（上行 R3 高 4 位为电能表通道特征——该仓库 SPEC 的 P0-01 缺陷记录确认应取 `pin[6]>>4` 高 4 位）。

### 2.6 地址域 A：BCD 6 字节 MAC，条件性出现

标准 6.3（表 6）：

| 地址域 | 数据格式 | 字节数 |
|---|---|---|
| 源地址 A1 | BCD | 6 |
| 中继地址 A2 | BCD | 6×中继级别 |
| 目的地址 A3 | BCD | 6 |

标准定义原文：

> a）**当信息域的"通信模块标识"为 0 时，无地址域 A**；
> b）当信息域的"通信模块标识"为 1 时，**主节点下行时，源地址 A1 是指主节点的 MAC 地址，中继地址 A2 和目的地址 A3 是指从节点的 MAC 地址；从节点上行时，源地址 A1 是指从节点的 MAC 地址，无中继地址 A2，目的地址 A3 是指主节点的 MAC 地址**；
> c）**当为广播命令时，目的地址 A3 为广播地址 999 999 999 999H**。

要点归纳：

1. **地址域是否存在**由信息域 R1 的 D2（通信模块标识）决定：0=无地址域（对主节点操作），1=有（对从节点操作）。因此 A 域长度只可能是 0 或 `12+6×中继级别` 字节（下行）或 12 字节（上行，无 A2）。
2. **地址含义**：是本地通信网中**主节点（集中器侧通信模块，即 CCO）与从节点（电能表侧通信模块/采集器）的 12 位 MAC 地址**（BCD 编码，每地址 6 字节）——既不是集中器的终端地址（那是 376.1 主站体系的 A1/A2/A3），也不是模块出厂号。中继场景下 A2 是路径上中继从节点的 MAC（仅下行携带，个数=中继级别）。
3. **BCD 与字节序**：地址为 BCD 码；按标准 5.2 总规则多字节"低字节在前"。实践上各厂商调试工具对 12 位 MAC 的显示顺序存在习惯差异（有的正序、有的逆序显示），**解析工具建议按帧内原始字节序展示，并在文档中说明（显示顺序待与目标厂家样例核对）**。
4. 广播帧：A3=999999999999H（12 个 9）。
5. 特例（标准表 123 说明，AFN=F1H 并发抄表）："当电表抄表失败时，报文长度域为 0，**链路层源地址域 A1 为失败电表的地址**"——即抄表失败时 A1 承载的是电表 645 地址（12 位 BCD），解析工具要按此特判。

### 2.7 应用数据域：AFN + DT（无 DA、无 SEQ）

标准 6.4：应用数据域 = 应用功能码 AFN(1B，二进制) + 数据单元标识 + 数据单元。

**数据单元标识 DT**（标准 6.4.3，图 6/图 7）：DT1（信息类元）+ DT2（信息类组）各 1 字节。DT2 二进制表示组号；DT1 按位（D0~D7）表示组内第 1~8 种信息类型。**Fn = DT2 × 8 + (DT1 中置 1 位的位序号 k)，k=1..8，n=1~248**。
- 例：DT1=01H、DT2=00H → F1；DT1=80H、DT2=18H(24) → 24×8+8=**F200**；DT1=08H、DT2=0CH(12) → 12×8+4=**F100**。
- **DT1 可以多位同时置 1**（一帧携带多个 Fn）。QGDW1376_2 的实现只取最高位（其 SPEC §2.3 明确登记为缺陷 P0），解析工具建议实现"逐位循环解析多 Fn"。

### 2.8 校验和 CS

标准原文 5.3.6：**"帧校验和是控制域和用户数据区所有字节的八位位组算术和，不考虑溢出位。"**

即：`CS = (C + R + A + AFN + DT + 数据单元) 之和 mod 256` = 帧内**从偏移 3（C）到偏移 len-3（最后一个数据字节）**的累加和低 8 位。

- **不含**：起始符 68H、长度域 2 字节、CS 自身、结束符 16H。
- 代码级印证：QGDW1376_2 `get_cs(pin+3, len-5)`；Xsoda `for(i=3;i<len-2;i++) sum+=packet[i]`（循环终值 len-2 即最后一个累加下标为 len-3）；South `self.cs = self.calculate_checksum(packed_frame[3:])`（对 C 起的字节求和）。
- 反向尝试结论：任务书提示的"若不匹配再试其他校验范围（如含 68H）"在本协议不成立——**所有已验证帧均以"C 起至数据末"命中**，含 68H 的累加从未命中。

### 2.9 结束符 16H、最小帧长

- 结束符固定 16H（偏移 len-1）。
- 最小合法帧 = 68(1)+L(2)+C(1)+R(6)+AFN(1)+DT(2)+CS(1)+16(1) = **15 字节**（L=0FH），实测语料中最小帧即 15 字节。
- QGDW1376_2 chkfrm 的输入下限保护是 11 字节（仅防越界，语义上 15 字节才是完整最小帧）。

## 3. 帧序域 SEQ：376.2 没有 SEQ

**结论：Q/GDW 1376.2 / 10376.2 的帧结构中没有帧序域 SEQ**（PSEQ/CON/FIR/FIN/TPV 均为 376.1 的 SEQ 概念）。证据：

1. 标准原文 6.1 用户数据区格式（图 4）只有"信息域 R、地址域 A、应用数据域"，应用数据域（图 5）="应用功能码 AFN、数据单元标识、数据单元"——无 SEQ。
2. 标准所有报文格式图（图 8 确认/否认、图 9 初始化、……）均为 `68H → L → C → R → A → AFN → 数据单元标识 → 数据单元 → CS → 16H`。
3. 四套实现中 AFN 均紧跟在地址域后（`pin[user_data_pos]` 即 AFN，`pin[user_data_pos+1..+2]` 即 DT1/DT2）。

**376.2 用什么实现 SEQ 的功能**：

| 376.1 的机制 | 376.2 的对应机制 |
|---|---|
| SEQ 的 PSEQ/RSEQ 帧序号（0~15） | 信息域 R 第 6 字节"**报文序列号**"（BIN 0~255 循环，"用以匹配上、下行报文的请求应答对应关系"，标准 6.2.1 k) / 6.2.2 i)） |
| SEQ 的 CON（需确认标志） | 由服务类别与命令性质决定：S2 发送/确认、S3 请求/响应（标准 5.4.1 表 3）；应答帧统一用 AFN=00H F1 确认 / F2 否认 |
| SEQ 的 FIR/FIN 分帧标志 | 未见等价定义（单帧即可承载 L1≤65529 字节的用户数据；长报文分帧依赖应用层数据单元内部结构，**待确认**：标准未定义链路层续传标志） |
| SEQ 的 TPV + 时间标签 Tp | 无对应（376.1 才有 6 字节 Tp 附加域） |

若工具界面要展示"帧序"，应展示**信息域 R6 报文序列号**，并注意上下行报文用它配对。

## 4. 传输规则（标准 5.2 / 5.3.2 / 5.4 / 5.5）

1. **字节格式**：8 数据位 + 1 起始位"0" + 1 偶校验位 P + 1 停止位"1"（8E1 异步），默认 9600 bit/s（"9600bit/s 或以上，默认为 9600bit/s"）。**字节内低位（D0）先传**。
2. **多字节字段**：低字节在前、高字节在后（长度 L、通信速率 R4~R5、以及一切多字节数值均小端）。
3. **线路空闲**为二进制 1；**帧内字符之间无空闲间隔**；检出差错后两帧之间线路空闲间隔最少 33 位。
4. **接收方校验**（标准原文顺序）：①每个字符校验起始位/停止位/偶校验位；②每帧校验固定报文头起始字符（68H）→ 识别长度 L → **每帧接收字符数 = L1+6** → 帧校验和 → 结束字符；任一失败舍弃此帧。
5. **链路传输服务**（标准 5.4.1 表 3）：S1 发送/无回答；S2 发送/确认（"当从动站正确收到…则发送确认帧；否则发送否认帧"）；S3 请求/响应（"从动站响应新的请求服务之前，必须完成前一个请求服务的响应"）。全双工接口可采用**平衡传输**（双方都可主动发起：大部分命令集中器为启动站；主动上报/路由抄读时模块为启动站——这与 C 域 DIR/PRM 组合呼应）。
6. **预留填充**：用户数据区所有预留部分用 0 填充（标准 6.1 注）。
7. **物理接口**：3.3V TTL 电平串口（标准 5.5），信号定义见 Q/GDW 10375.2—2019。

### 5.3 逐字节解析示例（选 3 帧）

**① D1 链路接口检测（下行）** `68 10 00 41 01 00 FF 00 00 00 04 01 00 00 46 16`

| 字节 | 字段 | 解析 |
|---|---|---|
| 68 | 起始符 | 68H |
| 10 00 | L | 0x0010=16=整帧总长（16 字节）✓ |
| 41 | C | DIR=0 下行，PRM=1 启动站，通信方式=1 集中式路由载波 |
| 01 | R1 | 路由标识=1（模块不带路由/旁路）；附属节点=0；通信模块标识=0（对主节点，无地址域）；冲突检测=0；中继级别=0 |
| 00 | R2 | 纠错编码=0 未编码；信道标识=0 不分信道 |
| FF | R3 | 预计应答字节数=255（延时按 255 字节估） |
| 00 00 | R4~R5 | 通信速率=0，单位 bit/s → 默认速率 |
| 00 | R6 | 报文序列号=0 |
| 04 | AFN | 04H 链路接口检测 |
| 01 00 | DT | DT1=01H、DT2=00H → **F1 发送测试** |
| 00 | 数据单元 | F1 无数据体（1 字节占位） |
| 46 | CS | 41+01+00+FF+00+00+00+04+01+00+00 = 0x146 → **0x46** ✓ |
| 16 | 结束符 | 16H |

**② U5 并发抄表上行（疑似现场帧）** `68 1E 00 83 04 00 00 00 00 32 72 57 28 09 00 00 00 00 00 00 00 00 F1 01 00 02 00 00 A7 16`

- L=0x001E=30=总长 ✓；C=83H：DIR=1 上行、PRM=0 **从动站**（模块被动响应）、通信方式=3（2019 版 HPLC / 2013 版宽带载波）。
- R=`04 00 00 00 00 32`：R1=04H→路由标识=0（带路由）、通信模块标识=0（对主节点，无地址域）、中继级别 0；R2=00 信道 0；R3~R4=00（相线/品质未报）；R5=00 事件标志=0；R6=32H 报文序列号。
- 应用数据=`F1 01 00 02 00 00`：AFN=F1H 并发抄表；DT1=01H、DT2=00H → F1 集中器主动并发抄表；数据单元=`02 00 00`→ 规约类型=02H（DL/T 645-2007）、报文长度=0x0000（低字节在前）→ **报文长度域为 0：抄表失败**（若带地址域，此处 A1 应为失败电表地址；本帧通信模块标识=0 无地址域）。
- CS=72+57+28+09+00+…+F1+01+00+02+00+00 累加=0x1A7 → **0xA7** ✓（CS 已验证）。

**③ D21 广播帧（构造）** `68 1C 00 41 04 00 00 00 00 02 12 01 00 00 00 01 99 99 99 99 99 99 05 04 00 01 FB 16`

- L=0x001C=28=总长 ✓；C=41H 下行启动、集中式路由载波；R1=04H→路由标识=0、**通信模块标识=1（对从节点）**→有地址域、中继级别 0。
- A1=`12 01 00 00 00 01`（主节点 MAC 示意）；A3=`99 99 99 99 99 99`=**广播地址 999999999999H** ✓（广播帧无 A2）。
- AFN=05H 控制命令；DT=`04 00`→F3 启动广播；数据单元=`01`。
- CS=0x1FB→**FB** ✓。

## 6. 与 376.1 帧格式的异同

| 对比项 | Q/GDW 376.1（主站↔终端） | Q/GDW 376.2（集中器↔本地通信模块） |
|---|---|---|
| 标准依据 | GB/T 18657.1 FT1.2，帧头 `68H` | 同为 FT1.2，帧头 `68H` |
| 帧头形态 | **68H + L(2B) + L(2B 重复) + 68H**（双起始符、长度发两遍） | **68H + L(2B)**（单起始符、长度仅一次） |
| 长度 L | 2 字节，**低 2 位是规约标志（D0=0、D1=1）**，D2~D15=用户数据长度 L1（BIN），L1=控制域+地址域+链路用户数据字节数；**不含** 68H/长度域/CS/16H；无线信道 ≤255、网络 ≤16383 | 2 字节纯 BIN，**无标志位**；**L=整帧总字节数**（=L1+6，含 68H/L/C/CS/16H）；≤65535 |
| 控制域 C | D7=DIR，D6=PRM，D5=FCB(下行)/ACD(上行)，D4=FCV(下行)/DFC(上行)，**D3~D0=功能码**（0 确认否认、1 复位、4 用户数据、8/9 链路测试、10/11 请求 1/2 级数据…） | D7=DIR，D6=PRM，**D5~D0=通信方式**（6bit：1/2 路由载波、3 HPLC[2019]/宽带[2013]、10 微功率、20 以太网）；**无功能码** |
| 地址域 A | **5 字节**：A1 行政区划码(2B BCD) + A2 终端地址(2B BIN) + A3 主站地址/组地址标志(1B BIN)；低位在前；A2=FFFF+A3.D0=1 为广播 | **0/12/18…字节 BCD MAC**：A1 源、A2 中继(仅下行、6B×中继级别)、A3 目的，每址 6B；通信模块标识=0 时整个 A 域缺失；广播 A3=999999999999H |
| 帧序域 SEQ | **有**：D7=TPV(时间标签有效)、D6=FIR、D5=FIN、D4=CON、D3~D0=PSEQ/RSEQ(0~15)；TPV=1 时帧尾附加 6 字节时间标签 Tp(PFC+时标 4B+延时 1B) | **无 SEQ**；请求/应答配对靠信息域 R6 报文序列号(0~255)；无分帧标志、无时间标签 |
| 信息点/信息类 | 数据单元标识=**DA(2B 信息点)+DT(2B 信息类)**，pn=DA1|DA2<<8，Fn=DT2×8+DT1 位序号 | 数据单元标识=**DT(2B)**，无 DA（信息点概念由地址域承载）；Fn 同算法 |
| 应用层 AFN | 00H 确认/否认，01H 复位，02H 链路接口检测，03H 中继站命令，04H 设置参数，05H 控制命令，06H 身份认证及密钥协商，0AH 查询参数，0CH/0DH/0EH 请求 1/2/3 类数据，0FH 文件传输，10H 数据转发，11H 登录 | 00H 确认/否认，01H 初始化，02H 数据转发，03H 查询数据，**04H 链路接口检测**，05H 控制命令，06H 主动上报，10H~15H 路由查询/设置/控制/数据转发/数据抄读/文件传输，F0H 内部调试，F1H 并发抄表（**注意两协议 AFN 语义不同**：376.1 的 02H 是链路接口检测，376.2 的 04H 才是） |
| 校验和 CS | 控制域+地址域+链路用户数据（即 C 起至数据末）算术和 mod 256 | 控制域+用户数据区（C 起至数据末）算术和 mod 256 —— **算法一致** |
| 结束符 | 16H | 16H |
| 链路服务 | S1/S2/S3、平衡传输 | S1/S2/S3、平衡传输（全双工接口） |
| 物理层 | 通常 2400~9600 8E1（远程信道） | 3.3V TTL UART，9600 8E1 默认 |
| 典型混淆点 | 376.1 的"链路检测"在 C 域功能码 9（帧）+ AFN=02H（登录/心跳） | 376.2 的"链路检测"是 **AFN=04H 链路接口检测**（C 域无功能码） |

**一句话总结**：两协议同属 FT1.2 家族、CS 算法一致、DIR/PRM 语义一致；但 376.2 的帧头去掉了重复长度和第二起始符，L 的语义从"载荷长度+标志位"改为"整帧总长"，控制域低 6 位从"FCB/FCV/功能码"改为"通信方式"，新增 6 字节上下行信息域 R 与条件性 BCD MAC 地址域，去掉了 SEQ/DA/Tp。**用 376.1 的帧解析器套 376.2 数据必然失败**（反之亦然），工具应以 68H 后第 1 字节的低位特征（376.1 的 L 低 2 位=10B vs 376.2 的 L 低位=长度数值）与总长关系做自动识别。

## 7. 解析工具实现要点（基于以上结论）

1. **切帧**：同步到 68H 后读 2 字节小端 L，收满 L 字节再校验尾 16H 与 CS；`L<已收` → 粘包（可继续解析后续帧），`L>已收` → 继续等待。L 理论上限 65535，缓冲区建议 ≥8192 字节（QGDW1376_2 用 8192）。
2. **校验顺序**（对齐标准 5.3.2）：68H → L 与实收字节数一致性 → 16H → CS。CS 错误建议单独报错码（如 ERR_CHKFRM_cs），便于区分"链路误码"与"结构错误"。
3. **字段边界**：C=pin[3]；R=pin[4..9]；有地址域时 AFN 偏移=22+6×中继级别（下行）/22（上行）；无地址域时 AFN 偏移=10。中继地址个数**只认下行**（上行即使 R1 高 4 位非 0 也无 A2，Xsoda 实现如此处理）。
4. **方向判定**：以 C 的 D7 为准；**不要**用"是否有地址域"或 PRM 推断方向（上行从动帧 C=8xH、下行从动帧 C=0xH 都存在）。
5. **多 Fn**：DT1 多位置 1 表示一帧多信息类，需按位循环解析；解析不了的内容以 HEX 转储兜底（AFN=F0H 厂家扩展同理）。
6. **特殊语义**：AFN=F1H 抄表失败（报文长度域=0，A1=电表地址）；AFN=00H F2 错误状态字表（§2.7）建议内置成中文提示；R3 预计应答字节数可用于超时估算。
7. **版本兼容**：通信方式 3 的文案按 2019 版显示"HPLC 载波通信"，可备注 2013 版为"宽带载波通信"；预留通信方式 4+（2024 版双模 HDC，待确认）与省级扩展 AFN（福建 50H~56H）的扩展点。
8. **显示建议**：MAC 地址按帧内字节序展示并提供反转显示开关；时间/数值字段一律按小端还原。
